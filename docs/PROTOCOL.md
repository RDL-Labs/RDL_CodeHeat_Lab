# CodeHeat/0.1

状態: EXPERIMENTAL / 有限なローカル参照実装。

## 問いと境界

問い: 固定環境・固定workloadの処理時間が、事前に指定した局所モデルから
どれだけ外れ、その差が反復して詳細検査を必要とするか。
実行結果の意味的正しさやコード修正の要否は、この判定だけでは決めません。

## イベント

JSON object、必須キーのみを許可:

| キー | 意味 |
|---|---|
| schema | `codeheat.span.v1` |
| run / event_id | run内で一意なイベント。再送時は同じIDと内容 |
| scope | 明示した処理境界 |
| environment | 実行環境manifestの参照。比較前に固定 |
| workload | 処理種別・入力条件manifestの参照 |
| start_ns / end_ns | 同じprocessの単調時計、整数ns |
| work_units | 正の有限値。例: 検査対象のray数 |
| status | `ok` / `error` |

識別子は1〜128文字。未知のキー・NaN・負値・時間逆転は明示拒否。
環境・workload参照文字列が一致するだけでは意味的同一性は保証されません。
ホスト・Python・コミット・計測条件をmanifestとして別途固定するのは実験側の責務です。
生の引数、ソースコード、秘密情報は収集しません。

## 固定モデルと局所規則

モデルはscope、environment、workloadに束縛された不変データです。

```text
expected_ns = ns_per_unit × work_units
E = (duration_ns − expected_ns) / expected_ns
H_pre = min(4θ, max(0, H_old − decay × 経過秒) + max(0, E))
```

Eは符号を保持します。初版のH加算は正の差だけに限定しています。
同じ入力数でも分布や処理内容が違えばこの線形近似は不適切になり得ます。
未モデル化のscope、環境・workload不一致、操作エラーは `not_comparable`。
その場合も実測時間は残し、Hは更新しません。

Hがθ以上で詳細要求が未発行なら、1〜16観測のdetail leaseを発行し、
局所検査cycleのHを0へ戻します。リセット前値も出力へ保存します。
これはモデルの修正・T1再構成ではありません。対象モデルは変更しません。
leaseは後続の比較可能イベントでのみ消費されます。時間失効はありません。
そのscopeにイベントが来なければ計測要求も消費されません。

単一Inspectorは1run・最大64scope・既定10000イベントまで。
満杯でも完全再送は既存receiptを返します。新規イベントは拒否し、暗黙に
古い記録を消しません。大規模運用では別の保存/集約契約が必要です。
同scopeの重なり・順序逆転は拒否。他scopeは独立。スレッド安全性は保証しません。

## Collectorと非介入の限界

collectorは明示的なcontext managerです。常駐hookや自動パッチを使いません。
sinkへの書込みは計測対象区間の後に行いますが、全体実行時間には負荷が加わります。
sinkの失敗は呼出し側へ伝播します。業務コードへ無断挿入する用途ではありません。
対象処理が例外になればerrorイベントを出して再送出します。
対象例外とsink例外が同時ならsink例外が表面に出るため、信頼できるsinkを使います。

本体が落ちれば終了イベントを保存できないことがあります。クラッシュ耐久性、
分散時計、永続exactly-once、CPU時間分離は初版の範囲外です。
通常実行と計測実行を分けて、観測器自身の負荷も必ず測ります。
